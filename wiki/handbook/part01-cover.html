How to use this handbook

This is not a reference manual you look things up in. It is a book you read in order, with the repository open beside it, running the commands as they appear.

MD Editor is roughly 26,000 lines of Rust across two crates. That is small enough to hold in your head eventually and large enough to be intimidating on day one. The path through it that this book takes is deliberate: outside in. You will see what the program does for a person, then the shape of the two crates, then the engine that owns the disk, then the editor that owns the screen, then the PDF machinery, and only at the end the rules that a contributor is expected to keep. By that point every rule will already have a story attached to it — which is the only way rules survive.

Conventions

Five kinds of aside appear throughout. They are worth learning to recognise, because each one is making a different kind of promise to you.

Why it is like this The reasoning behind a decision that looks arbitrary. If you ever want to change the code these describe, you have to defeat the argument in the box first.
Trap A mistake this codebase has actually made, or one it is shaped to invite. These are the paragraphs that save you an afternoon.
Try it Something to run or change right now, in the checkout in front of you. Reading about a Fenwick tree is not the same as watching one stop your editor from stalling.
Check yourself A question with an answer directly underneath. If the answer surprises you, re-read the section — the material after it assumes you got this one.
Note Context, history, or a pointer somewhere else in the book.

Source references look like core/src/vault.rs::write_file — a path relative to the repository root, and where useful the function inside it. Every factual claim in this book is meant to be checkable against the file named beside it. Where a claim and the code disagree, the code is right and this book has a bug; the same rule the wiki holds itself to.

What you need in front of you

  • A clone of the repository, on the default branch.
  • A stable Rust toolchain, 1.85 or newer — the workspace is on the 2024 edition.
  • A C compiler, because rusqlite builds SQLite from source.
  • Network access for the first build only, so the build script can fetch PDFium.
  • A desktop session, if you want to run the app. The core crate's tests need no display at all.

Chapter 3 walks the whole setup. If a command in this book fails, that chapter is where the fix lives.
